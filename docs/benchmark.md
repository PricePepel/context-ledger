# M0 benchmark: graph context vs Markdown handoff

Generated by `bench/m0.mjs` on 2026-11-07 at commit `961623f2e064`, seed 42. All transcripts are synthetic. Everything except timings, date, commit and machine is deterministic for a seed.

Reproduce:

```sh
node bench/m0.mjs --seed 42 --sizes 10,50,200,1000 --reps 20 --append 10 --markdown docs/benchmark.md
```

Machine: Node v22.23.4, linux x64, 4 x Intel(R) Xeon(R) Processor @ 2.30GHz.

Each size is the number of conversation turns per party. Party `mara` is a Claude Code JSONL transcript and party `teo` a Codex rollout; `teo` links to `mara` with matches, conflicts and answers, and the two graphs open one room.

## 3. Cache-prefix stability

Method: 10 turns are appended to the transcript and it is imported again. The store keys a session by the hash of its transcript, so the longer transcript becomes a new session. A revised graph with the same nodes plus one new action is published against it. The table shows the longest common leading prefix of the old and new output, in characters, as a share of the new output, once as is and once comparing the texts with every session and graph ID replaced by the same placeholder on both sides ("IDs constant"), so a single changed ID line does not decide the comparison. Both shares use the original new output as the denominator: a placeholder inside the matching prefix counts as the full ID it stands for. Tokens are estimated as characters / 4, like the meter. A prefix counts as cache-eligible only from 1024 estimated tokens, the safe minimum across Anthropic's older models and OpenAI (the newest Claude models accept 512).

| 10 | mara (claude) | 50.8% | 149 | 50.8% | 2.7% | 21 | 59.1% | 452 | 1 |
| 10 | teo (codex) | 42.2% | 148 | 42.2% | 2.6% | 21 | 59.7% | 469 | 1 |
| 50 | mara (claude) | 49.4% | 193 | 49.4% | 1.0% | 21 | 83.7% | 1709 (eligible) | 1 |
| 50 | teo (codex) | 45.4% | 212 | 45.4% | 1.0% | 21 | 84.6% | 1675 (eligible) | 1 |
| 200 | mara (claude) | 53.1% | 294 | 53.1% | 0.3% | 21 | 94.9% | 6131 (eligible) | 1 |
| 200 | teo (codex) | 44.6% | 300 | 44.6% | 0.3% | 21 | 95.2% | 6255 (eligible) | 1 |
| 1000 | mara (claude) | 54.8% | 540 | 54.8% | 0.1% | 21 | 99.0% | 30116 (eligible) | 1 |
| 1000 | teo (codex) | 47.6% | 561 | 47.6% | 0.1% | 21 | 99.0% | 29840 (eligible) | 1 |

As is, the handoff keeps 0.1% to 2.7% of its characters as a common prefix, and at every size the prefix ends inside its `Session:` line, because the session ID is a hash of the whole transcript and changes with every append. With session and graph IDs held constant the handoff keeps 59.1% to 99.0%: after the ID line it is append-only. The graph context keeps 42.2% to 54.8% as is and 42.2% to 54.8% with IDs held constant; its prefix ends in the middle because the new action also adds an `advances` edge, and the edges section comes before links and actions.

Cache-eligible stable prefix (at least 1024 estimated tokens): graph context at no size; handoff as is at no size; handoff with IDs held constant at 50, 200, 1000 turns. So the graph context is smaller, but it is not the more cache-stable format here: at every size a handoff with its IDs held constant keeps a larger share of its characters as a common prefix than the graph context.

## Method and limits

- Inputs are synthetic negotiations from a seeded PRNG (mulberry32). Most turns are filler work chatter; planted facts (about sqrt(turns) + 4 per party) sit at known lines. Real sessions have longer turns, tool output and code, so absolute sizes and ratios will differ.
- The benchmark writes the graph packets itself. It measures storage, canonicalisation and rendering through the real HTTP API, not how well an agent extracts a graph from a transcript.
- Token figures are estimated as characters / 4 and are not tokenizer counts. Real counts vary by model (Claude 4.7 and later tokenizers emit about 30% more tokens for the same text) and by content: structured text, digits and code usually yield more tokens per character than prose, so the token saving may differ from the character saving. Section 6 shows the content mix of each side.
- The graph context is compared with the full Markdown handoff of the same transcript, which is the baseline the API meter uses. A hand-written summary would be a different, smaller baseline.
- Cache savings need a prefix above the provider minimum and a follow-up request within the cache lifetime. Changing tools, the system prompt or thinking settings invalidates a cache whatever Context Ledger outputs.
- Input limits: sizes run from 2 to 9215 turns, because the revised packet (about sqrt(turns) + 5 nodes) must fit the v2 schema limit of 100 nodes; each import body must stay under the server's 8 MiB request limit; seeds run from 0 to 4294967295. The benchmark checks these before it starts the server.
- The server runs as a child process on a free loopback port with a fresh temporary database, which is deleted at the end, also on an error or on SIGINT, SIGTERM or SIGHUP (a signal writes no report and exits with 128 + the signal number). Latency includes local HTTP and JSON overhead and is a single-machine measurement.
