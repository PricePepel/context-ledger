# G6 product and eval review (2026-11-17)

## 1) What the product does today

Context Ledger imports user-selected Claude Code and Codex transcripts into local SQLite, searches their conversational turns, and exports Markdown handoffs with original line numbers. Agents can publish typed graphs, read compact briefings over MCP, and open a browser room where two parties can record choices on proposals. An optional local model answers questions about selected files, with a numbered-text fallback, and the repository includes experimental latent transfer and team runners.

## 3) Three biggest risks to a user

1. **Correctness — a real citation can support the wrong action.** The graph validator checks that the cited turn exists. A label can still reverse its meaning or repeat an obsolete value. Cycle 7 caught a stale conflict in rehearsal. PR #23's proposed `quoted` mark can pass on one shared content word. See `src/graph.mjs`, Cycle 7 and the G7 branch handoff.
2. **Privacy — a local ledger can send raw text into an agent's context.** SQLite keeps imported turns and MCP exposes them through `session_read`. When the local model is unavailable, `latent_read` deliberately returns numbered file text. If the caller uses a hosted model, that text can leave the machine. See the README's data and fallback sections, `src/mcp/sessions.mjs` and the Cycle 6 fallback eval.
3. **Trust — “agreed” can look like verified approval.** Party names are self-asserted. The browser flow records choices under those names without authenticating either person. Cycle 4 proves the two-choice rule. Use the room status as a local record of choices. See `src/server.mjs`, `src/rooms.mjs` and the README's negotiation section.

## 4) Recommended next cycle

**Goal.** Establish whether a receiving agent can recover the current facts from a cited briefing with fewer input tokens than from the full transcript.

**Acceptance eval, before code.** Run G10 with a pinned model in each of Claude Code and Codex. Use the existing 14-fact fixture and two held-out synthetic handoffs with independently reviewed answer keys. Put changed decisions and essential facts after page one. Human-check the 82 grader labels and audit the live replies for unsupported additions and wrong citations. Alternate arm order and require at least 10 valid paired runs per fixture and client. Count failed, invalid and timed-out attempts as failures. Pass if the graph arm gets all facts and their supporting lines right in at least 90% of attempts on each client, matches or beats the transcript arm's all-facts pass rate, and uses at least 30% fewer median input tokens. Report publishing time and tokens separately, along with receiving latency and failures.

**Defer** orchestration, more latent scaling, and new dashboard work for this cycle. Hold the general “3× faster, 5× fewer tokens” claim until a benchmark supports it.
